# TradeSim Terminal v2.0: Algorithmic Trading Simulator & Backtester

**TradeSim** — це високопродуктивна клієнт-серверна система для розробки, тестування та аналізу алгоритмічних торгових стратегій.

Проєкт дозволяє перевіряти торгові гіпотези на великих історичних даних (бектестинг), керувати ордерами та аналізувати ринкову ситуацію через зручний графічний інтерфейс, використовуючи сучасні підходи до проєктування програмного забезпечення та паралельних обчислень.

---

## Основний функціонал

- **Мультипоточний Бектестинг:** Високопродуктивний рушій для тестування стратегій на масивах до 5 000 000 котирувань. Використовує паралельні обчислення (Worker Threads) для досягнення прискорення у понад 2.4x разів порівняно з послідовним виконанням.
- **Інтерактивний GUI (Terminal v2.0):** Сучасний веб-інтерфейс із вбудованим модулем бенчмаркінгу для візуального порівняння швидкодії (Sequential vs Parallel).
- **Гнучкий конструктор стратегій:** Динамічне перемикання між торговими алгоритмами (Moving Average, RSI) "на льоту".
- **Керування ордерами (Order Management):** Повний життєвий цикл ордерів (Pending, Filled, Canceled) із можливістю скасування останньої дії (Undo).
- **Збереження даних:** Надійне зберігання історії транзакцій у реляційній базі даних (PostgreSQL).

## Технологічний стек

Проєкт розділено на незалежні клієнтську та серверну частини (REST API):

**Frontend (Клієнт):**

**Backend (Сервер):**
- **Core:** Node.js, Express, TypeScript, `worker_threads`

## Архітектура та Патерни проєктування (GoF)

Бекенд системи побудовано з використанням **12 класичних патернів проєктування**, що забезпечує низьку зв'язність (Low Coupling) та високу гнучкість:

**Твірні:**
- `Singleton` (TradeHistory) — єдиний глобальний стан історії.
- `Factory Method` (OrderFactory) — інкапсуляція створення Market та Limit ордерів.

**Структурні:**
- `Proxy` (CachedPriceProxy) — кешування запитів до біржі.
- `Facade` (TradingFacade) — спрощений інтерфейс для швидкої торгівлі.
- `Decorator` (OrderDecorator) — динамічне додавання комісій до ордерів.
- `Adapter` (BinanceAdapter) — інтеграція із зовнішніми API.
- `Composite` (CompositeOrder) — групування кількох ордерів в один масив.

**Поведінкові:**
- `Strategy` (TradingStrategy) — взаємозамінні торгові алгоритми.
- `Command` (PlaceOrderCommand) — інкапсуляція запитів та функція Undo.
- `State` (OrderState) — керування станами ордера (Pending/Filled/Canceled).
- `Observer` (TradeNotifier) — реактивна система сповіщень (Event Driven).
- `Template Method` (BacktestTemplate) — каркас для алгоритмів бектестингу.

## Мультипоточність та Оптимізація

Для обробки великих масивів історичних даних (до 5 млн записів) реалізовано модуль алгоритмічного бектестингу `BacktestService`:

- **Worker Threads:** Головний потік нарізає масив даних (`Float64Array`) на рівні частини (`chunks`) та делегує важкі математичні розрахунки ізольованим потокам. Результати агрегуються за допомогою `Promise.all()`.
- **Data Overlap (Вирішення проблеми межових станів):** Оскільки торговим індикаторам потрібна історія попередніх свічок, алгоритм розподілу перекриває дані на межах потоків (`startIdx -= 100`). Це гарантує ідентичність математичних результатів між послідовним та паралельним виконанням без втрати торгових сигналів.

**Бенчмарки швидкодії (Intel / AMD Test):**

| Обсяг даних | Послідовно (1 потік) | Паралельно (4 потоки) | Прискорення |
| :--- | :--- | :--- | :--- |
| **1 000 000 записів** | ~1927 мс | ~1024 мс | **~1.88x** |
| **5 000 000 записів** | ~9496 мс | ~3944 мс | **~2.41x** |

## Встановлення та запуск

### 1. Клонування репозиторію

```bash
git clone https://github.com/raychiikk/TradeSim.git
cd TradeSim
```

### 2. Налаштування Backend

```bash
cd backend
npm install
```

- Створіть файл `.env` та додайте `DATABASE_URL` для підключення до PostgreSQL.
- Застосуйте міграції БД та згенеруйте клієнт Prisma:

```bash
npx prisma db push
npx prisma generate
```

- Запуск сервера:

```bash
npm run dev
```

### 3. Налаштування Frontend

Відкрийте новий термінал у корені проєкту:

```bash
cd frontend
npm install
npm run dev
```

### 4. Документація та Тести

- Запуск Unit-тестів: `npm run test` (у папці `backend`)
- Генерація TypeDoc документації: `npm run docs` (у папці `backend`)
